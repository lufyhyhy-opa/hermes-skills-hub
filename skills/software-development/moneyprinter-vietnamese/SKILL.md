# Vietnamese MoneyPrinterV2

## When to Use

Use this for localization or recovery of FujiwaraChoki/MoneyPrinterV2 on macOS.

## Start from actual state

Locate an existing checkout before cloning. Snapshot dirty source/config/output before edits and keep credentials out of the deliverable archive. If the terminal workdir validator rejects decomposed Vietnamese Unicode, use a symlink with an ASCII path; do not move the original repo. Resolve application ROOT_DIR from __file__, never sys.path[0].

## Dependency compatibility

Use Python 3.11 or 3.12 and a project venv. Pin moviepy==1.0.3 and Pillow==10.4.0; restore Image.ANTIALIAS via Image.Resampling.LANCZOS if a MoviePy path uses it. NumPy1.26.4 avoids old MoviePy incompatibilities. gTTS2.5.4 needs Click<8.2 while huggingface-hub2.x needs newer Click: constrain huggingface-hub>=0.21,<1.0 and verify pip check. selenium_firefox2.0.8 imports FirefoxBinary removed from later Selenium: Selenium4.27.1 imports successfully. Verify imports, not only resolver output. Remove mandatory KittenTTS for Vietnamese.

## Content and providers

Route explicit content kinds: topic, four-sentence script, title, description, four English image_prompts JSON strings, X, affiliate and outreach. Test each independently; substring-based prompts can fall through to generic scripts. Reject HTML/error bodies and malformed prompt arrays. Support actual installed Ollama model selection, optional Gemini, bounded Pollinations calls and specialist local templates. A saved API key alone must not enable spending. Label templates and designed Pillow cards honestly. Free endpoints can intermittently work or return errors within the same cycle.

Use gTTS lang=vi -> FFmpeg atempo=1.15 mono24000 WAV -> installed macOS Linh -> edge-tts vi-VN-HoaiMyNeural. Bound providers in subprocesses and validate audible decoded WAV. Label final warning tone is_speech=false; do not count it as a narrated Short. Preserve _find_ffmpeg for callers.

## Durable generation and data truth

Keep browsers lazy and the production runner draft-only explicitly, including post(live=False). Do not auto-send SMTP because credentials exist. Parse actual public site HTML for prospects and public contacts; record source_url, retrieved_at and email_source. Leave missing emails empty, never fabricate companies/contacts. Escape company/hook text in personalized HTML. Label seed product homepage URLs example_not_enrolled instead of inventing referral IDs or commissions.

Use atomic file replace plus advisory locks for JSON append. Fail on corrupt history while preserving the original. Save MP4+JSON+SRT and narration/images under output/ so cache cleanup cannot erase them. Ledger counts must come from observed artifacts, with unmeasured revenue/compute cost null. Compare physical file/record counts to ledger by run_id. Checkpoint generated outputs before committing ledger updates; upsert by run_id plus workflow and retain the original successful timestamp so resume cannot postpone the scheduler. Fingerprint cumulative JSON by selected record IDs and canonical content, since later appends legitimately change the full file hash. Require exactly one stored row per requested ID before building hash dictionaries; sets/dicts can hide duplicated IDs or balance a missing ID with a duplicate. Count affiliate output by unique persisted IDs, not product configuration rows. Keep per-run immutable CSV/source snapshots for outreach and reuse the aggregate source-history row by run_id on interrupted retries. Validate the selected run strictly, and report old failed/partial output separately so a retained orphan cannot permanently block later successful acceptance. Verify resume on an actual completed cycle by comparing artifact hashes and complete ledger before/after, not only by mocked generator call counts. Include narration and images in video integrity checkpoints, reject missing hashes on recovery, and make cache inserts idempotent by video identity.

## Editorial Shorts and local Content Studio

Choose this route for task-teaching Vietnamese Shorts generated by the existing MoneyPrinterV2 workflow; do not substitute a cinematic Remotion promo template merely because it is video. Keep any hand-built task illustration clearly labeled as an illustrative example, never as a real customer, campaign, or measured result. Preserve the selected prompt and full scene/storyboard content as output sidecars so a rendered video remains inspectable and reusable.

For a scene-based Short, validate a known editorial example has all required scenes before synthesis. Generate Vietnamese speech per scene, reject a degraded/non-speech segment immediately, measure each valid mono 24000 Hz WAV, and derive scene starts and transitions from those exact sample counts. Concatenate in scene order. Place exact narration text in SRT per scene; timing within each scene may be estimated from text length, but label that limitation while keeping scene boundaries tied to measured audio. Render a poster/storyboard and persist every scene WAV, prompt, narration, subtitle, and both music variants when applicable in the same output-scoped kit. Add every file to the sidecar artifact list and integrity map before checkpointing. Keep custom-topic or unknown catalog entries on their existing safe path rather than silently substituting an unrelated example.

Inspect the real poster and representative frames at phone scale. Confirm text is readable and not clipped, scene order illustrates the narrated task, and the video has real speech and valid dimensions. Decode the complete MP4 with FFmpeg; mocked renderer/TTS tests prove integration shape only, not a successful production Short.

### Renderer and sidecar contract

Native renderer API is `render_short(scenes, durations, narration_path, output_path, workspace, *, subtitles=None, music_path=None, fps=24, threads=2)`. Expect return keys `poster_path`, `storyboard_path`, optional `no_music_path`, and scene timeline under **`scene_timings` or `scenes`** (also accept legacy `scene_timing`). Map into the sidecar as one stable field and keep both names if downstream already reads one. Store **both** `artifact_integrity` and `integrity` digests — the studio normalizer may look for either. Refuse replacing an existing output path; keep renderer work in an owned child of the attempt workspace and only publish via exclusive create/copy. When music is mixed, keep a narration-only variant in the kit.

### Content Studio (Operate primary)

Default surface is **Operate**: searchable selectable product list + detail inspector (preview / full content / prompts / sources), not a marketing hero. Monitor (daemon/runs) stays secondary. Normalize from real persisted records only: full plain-text `content`/`sections`/`prompts`, `media.{video,poster,narration}` as output-relative URLs or null, http(s) `sources` only. Convert outreach HTML bodies to plain text — never execute `body_html`. Define readiness states `ready_for_review` | `needs_input` | `unavailable` as **technical completeness for review**, never publish approval; keep unmeasured metrics null. A GET-only ZIP at `/api/export/<channel>/<id>` must match **exactly one** record; reject unknown/ambiguous IDs; include content.txt + normalized metadata + allowlisted existing output files only — never cumulative history, run manifests, config, credentials, or basename fallbacks outside output. Restart the localhost dashboard process after changing `dashboard.py`/`serve_dashboard.py` so `/api/status` is not still serving a stale import.

### Resume and inventory truth

After `--resume`, do **not** hash the whole `output/` tree as proof of no regeneration — `dashboard.html` rebuilds and run manifests bump `updated_at`. Hash product channels only (shorts kit, twitter/affiliate/outreach JSON/CSV) plus ledger workflow attempts/status. Missing physical files must not inherit ledger totals as inventory.

### Parallel ownership

When splitting workers: one owns studio data/export/server tests, one owns `assets/dashboard.html` only, one owns `content_examples`/`shorts_studio` only; parent owns YouTube/cron integration, real `--once`, decode, package, daemon. Read worker return dicts against live source before the production cycle — do not assume the brief’s key names match the implementation.

Hold automated UI tests/linters until the user likes the design or is about to commit; manual screenshots and backend/media checks remain allowed.

Run preflight, actual --once all, decode the entire MP4 with FFmpeg, inspect a frame and confirm speech (local cached Whisper is useful). Programmatically parse/count every JSON/CSV. Exercise daemon start/status/stop/duplicate start, lock contention and error propagation. Use a separate process group for a daemon's cycle so termination covers child renderers. Stop must SIGTERM then SIGKILL and return nonzero while the worker is still alive. Defer the first daemon cycle only when one complete latest run_id already succeeded. Detached 8-hour loops still stop at reboot and cannot produce during machine sleep; state that explicitly. Isolate ledger write failures so remaining workflows still run and preserve recovery facts without resetting the ledger. Reject non-speech before rendering a Short. Verify current record IDs by run_id, not only cumulative file size. Never pkill user Firefox; only quit owned browser objects.

Legacy tests may install persistent sys.modules stand-ins. Remove stale global stubs or execute unittest modules in isolated subprocesses; never accept mocked imports as proof the actual pipeline runs. If requested by the host verification gate, create hermes-verify-*.py via tempfile in the exact requested OS temp directory, execute behavior checks, remove it, and label the report ad-hoc verification. Put `sys.path.insert(0, <repo>/src)` **before** importing project modules inside the probe — the probe runs outside the package layout and bare `from dashboard import ...` will fail after the tests already passed. Save real result JSON and provide actual artifacts before claiming completion.
